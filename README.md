# 大创项目：财政约束、政府风险偏好与地区创新产出

## 研究问题

> 财政约束是否会通过改变政府的风险偏好，从而扭曲耐心资本的角色，进而影响地区创新产出？

理论框架：**财政约束 (X) → 政府风险偏好 (M) → 地区创新产出 (Y)**

详见 `新思路.md`。

### 回归结果摘要

采用双向固定效应 (城市FE + 年份FE)，城市层面聚类标准误。

#### 基准回归 (Part A)

| 模型 | 被解释变量 | 核心变量系数 | 显著性 |
|------|-----------|-------------|--------|
| A1 (无控制) | ln\_发明专利申请数 | 1.773 | \*\* |
| A2 (含控制) | ln\_发明专利申请数 | 1.701 | \*\* |
| A3 (稳健性) | ln\_专利申请受理数 | 0.164 | 不显著 |
| A4 (稳健性) | ln\_专利授权数 | 1.406 | \* |

控制变量：ln\_人均GDP、第二产业占比、科技支出占比、ln\_人口

#### 机制检验 (Part B-D)

| 模型 | 路径 | 系数 | 显著性 |
|------|------|------|--------|
| B1 | 财政缺口率 → 早期投资事件占比 | 1.596 | 不显著 (p=0.11) |
| B2 | 财政缺口率 → 加权风险偏好指数 | 3.639 | 不显著 (p=0.12) |
| C1 | 早期投资事件占比 → ln\_发明专利 | 0.007 | 不显著 |
| C2 | 加权风险偏好指数 → ln\_发明专利 | 0.004 | 不显著 |
| D1 | 同时加入: 财政缺口系数 | 1.736 | \*\* (未减小) |

**结论：中介效应不成立。** 机制变量 (风险偏好) 既不受财政约束显著影响，也不显著影响创新产出。

## ⚠️ 已知问题

### 1. 🔴 基准回归系数方向与理论预期相反

财政缺口率对创新产出的系数为**正** (1.70\*\*)，即财政缺口越大 → 专利越多。理论预期为负。

可能原因：
- 样本限于有引导基金投资的城市，存在**选择偏差**
- **反向因果**：创新活跃/快速发展城市的公共支出也大
- 缺少足够的工具变量来处理内生性

### 2. 🔴 专利数据为省级而非地级市

当前专利数据来自 CSMAR，只有省级和副省级城市有独立数据。大部分地级市被匹配到了所在省份的数据，导致**同省城市共享一个被解释变量值**，组内变异大幅丧失。

**需要：地级市层面的专利申请/授权数据**（如 CNRDS 或国家知识产权局地级市统计）

### 3. 🟡 中介机制不成立

B 步骤 (财政约束→风险偏好) 和 C 步骤 (风险偏好→创新) 均不显著，中介效应无法验证。需要考虑：
- 机制变量的度量方式是否合理
- 是否存在调节效应而非中介效应
- 引导基金投资阶段分类数据质量

### 4. 🟡 缺漏数据

| 数据 | 用途 | 重要性 |
|------|------|--------|
| **地级市专利数据** | 被解释变量 | 🔴 高 |
| 高等学校在校生数 | 控制变量 (人力资本) | 🟡 中 |
| 引导基金自身规模/数量 | 基金层面控制变量 | 🟡 中 |
| 市场化VC早期投资数据 | 安慰剂检验 | 🟡 中 |

### 5. 🟢 外资占比异常值

`外资占比` max=11.8，存在明显异常值，需 winsorize 处理。

## 获取和使用数据

当前分支的数据使用普通 Git 保存，不需要 Git LFS。小于 100,000,000 字节的原数据、面板表、结果表和 PDF 直接按原路径跟踪。较大 CSV 按原始字节拆成分片，每片最多 95,000,000 字节；清单位于 `data_parts/manifest.json`。

克隆本分支后，在仓库根目录执行：

```bash
python3 scripts/data_parts.py restore
```

命令会校验分片并在原路径重建 CSV。重建后的文件与原文件的字节数和 SHA256 一致，编码、BOM、表头、引号和换行均保留，原有 Stata/Python/R 读取路径不需要修改。已有且校验一致的 CSV 会跳过；已有但内容不同的文件会保留并报错，避免覆盖修改。

这些分片是二进制片段，不能各自作为完整 CSV 读取，也不要用 pandas.concat 直接拼接分片。恢复后的大 CSV 已按精确路径加入忽略规则；提交的是分片与清单。

仅验证分片而不生成 CSV：

```bash
python3 scripts/data_parts.py verify
```

## 数据更新与提交

修改大 CSV 后，先将旧 `data_parts/manifest.json` 备份到仓库外（工具默认拒绝覆盖不同版本的清单），再使用 `scripts/data_parts.py split --source-root . --paths-json <清单.json>` 重新生成分片。输入为 JSON 列表，每项包含 `path`、`size` 和 `sha256`，应填写修改后文件的实际大小和哈希；输出清单和分片仍保存在 `data_parts/`。提交新清单和新分片，不提交重建的大 CSV。旧清单不再引用的分片应在核对后移除，避免保留重复数据。

安装本仓库的提交检查：

```bash
git config core.hooksPath .githooks
```

也可以随时手动检查暂存区：

```bash
python3 scripts/sync_git_lfs_by_size.py --check
```

检查会拒绝残留 LFS 指针、大小达到 100,000,000 字节的 Git 文件，以及未解决的合并冲突；不会自动修改数据或暂存区。脚本名称为兼容原有工作流保留。
